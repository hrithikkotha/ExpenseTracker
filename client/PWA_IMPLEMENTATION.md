# PWA Implementation Guide

This document explains the Progressive Web App (PWA) implementation in the Expense Tracker application.

## Overview

The application has been converted into a full-featured PWA with:
- **Installability** on Android, iOS, Windows, and macOS
- **Offline functionality** with intelligent caching
- **Background synchronization** for offline transactions
- **Automatic updates** when new versions are deployed
- **Native app-like experience** with standalone display mode

---

## Architecture

### 1. Service Worker (via Vite PWA Plugin)

**Location**: Automatically generated by `vite-plugin-pwa`

**Configuration**: `client/vite.config.ts`

**Caching Strategies**:
- **App Shell** (HTML, CSS, JS): Cache First
- **Images**: Cache First with 30-day expiration
- **Fonts**: Cache First with 1-year expiration
- **API Calls** (GET): Network First with 5-minute cache fallback
- **API Mutations** (POST/PUT/DELETE): Network Only (never cached)

### 2. IndexedDB Storage (via Dexie.js)

**Location**: `client/src/pwa/db.ts`

**Tables**:
- `transactions` - Offline transactions (both pending and cached)
- `accounts` - Cached accounts for offline viewing
- `budgets` - Cached budgets for offline viewing
- `syncQueue` - Queue of operations to sync with server
- `metadata` - App metadata and settings

**Purpose**: Store offline data and queue changes for synchronization.

### 3. Background Sync Service

**Location**: `client/src/pwa/sync/backgroundSync.ts`

**Features**:
- Automatically syncs when connection is restored
- Intelligent retry logic (max 3 attempts)
- Batch processing to avoid overwhelming the server
- Callback system for sync status notifications

**How it works**:
1. User creates/updates/deletes data while offline
2. Operation is saved to IndexedDB and added to sync queue
3. When online, background sync automatically processes the queue
4. Success: Remove from queue, update local data
5. Failure: Mark as failed, retry later

### 4. Network Status Monitoring

**Location**: `client/src/pwa/hooks/useNetworkStatus.ts`

**Features**:
- Real-time online/offline detection
- Connection quality monitoring (4G, 3G, 2G)
- Bandwidth and latency tracking

### 5. Offline Storage Hooks

**Key Hooks**:
- `useNetworkStatus()` - Monitor network connectivity
- `useSyncStatus()` - Track sync queue status
- `useOfflineTransactions()` - Manage offline transactions

## How Offline Mode Works

### Creating Transactions Offline

1. **User attempts to create a transaction while offline**:
   - Transaction is saved to IndexedDB (`transactions` table)
   - Operation is added to sync queue
   - UI immediately shows the transaction (optimistic UI)
   - User sees "Will sync when online" indicator

2. **When connection is restored**:
   - Background sync automatically detects online status
   - Processes sync queue sequentially
   - Creates transaction on server
   - Updates local transaction with server ID
   - Removes from sync queue

3. **User experience**:
   - Seamless - no manual sync required
   - Immediate feedback - transaction appears instantly
   - Visual indicators - pending sync badge shows count
   - Error handling - retry logic with user notification

### Viewing Data Offline

**Cached Data**:
- Last fetched transactions (up to 100)
- All accounts
- All budgets
- Dashboard analytics (from cached data)

**What Works Offline**:
- ✅ View dashboard
- ✅ View transactions list
- ✅ View calendar
- ✅ View accounts
- ✅ Create new transactions (synced later)
- ✅ View charts (from cached data)

**What Doesn't Work Offline**:
- ❌ Update existing transactions (requires server)
- ❌ Delete transactions (requires server)
- ❌ Create accounts (requires server)
- ❌ Export data (requires server generation)

## Installation Flow

### Desktop (Chrome, Edge, etc.)

1. Visit the app in Chrome/Edge
2. Look for install icon in address bar (or "Install" button in app)
3. Click install → App opens in standalone window
4. Appears in Start Menu / Applications folder
5. Can be launched like any desktop app

### Android

1. Visit app in Chrome
2. See "Add to Home Screen" prompt
3. Tap "Install" → App installs
4. Icon appears on home screen
5. Opens fullscreen without browser UI

### iOS (Safari)

1. Visit app in Safari
2. Tap Share button
3. Select "Add to Home Screen"
4. Confirm → App icon appears on home screen
5. Opens in standalone mode

**Note**: iOS has limited PWA support (no background sync, no push notifications).

## Caching Strategy Details

### Static Assets

```
Strategy: Cache First
Expiration: Never (unless cache version changes)
Files: HTML, CSS, JS, fonts, icons
```

### API Endpoints

```
GET /api/v1/transactions  → Network First (5min cache)
GET /api/v1/accounts      → Network First (5min cache)
GET /api/v1/budgets       → Network First (5min cache)
POST/PUT/DELETE /api/*    → Network Only (never cached)
```

### Images

```
Strategy: Cache First
Expiration: 30 days
Max Entries: 60 images
```

### Fonts

```
Strategy: Cache First
Expiration: 1 year
Max Entries: 10 fonts
```

## Update Mechanism

### How Updates Work

1. **New deployment**: Server has new version
2. **Service worker**: Detects new version available
3. **User notification**: "A new version is available!"
4. **User action**: Click "Update Now"
5. **App reloads**: New version loads immediately

### Automatic Update Checks

- **On page load**: Check for updates
- **On visibility change**: Check when user returns to tab
- **Every hour**: Periodic update check (if app is open)

## Security Considerations

### What is NOT Cached

- ❌ Authentication tokens (JWT)
- ❌ Authorization headers
- ❌ Sensitive user data (passwords, etc.)
- ❌ Private API responses (POST/PUT/DELETE)

### What IS Cached

- ✅ Public static assets
- ✅ Non-sensitive transaction data
- ✅ Account balances (encrypted at rest)
- ✅ App shell (HTML, CSS, JS)

### HTTPS Requirement

**PWAs only work over HTTPS** (or localhost for development).

- Service workers require secure context
- Install prompt requires HTTPS
- Background sync requires HTTPS

## Troubleshooting

### Service Worker Not Registering

**Check**:
1. Running on HTTPS (or localhost)
2. No console errors in Network tab
3. Service worker file is accessible
4. Browser supports service workers

**Fix**:
```bash
# Clear browser cache
# Unregister old service workers
# Hard refresh (Ctrl+Shift+R)
```

### Install Prompt Not Showing

**Reasons**:
1. App already installed
2. User dismissed prompt recently (7-day cooldown)
3. Browser doesn't support install (iOS Safari requires manual)
4. Manifest.json not accessible

**Fix**:
```bash
# Check manifest in DevTools → Application → Manifest
# Check console for manifest errors
# Clear localStorage: `pwa-install-dismissed`
```

### Sync Not Working

**Check**:
1. Network status (must be online)
2. Sync queue has pending items
3. No auth errors (token valid)
4. Background sync is enabled

**Debug**:
```typescript
// Check sync queue
import { getSyncQueueStats } from '@/pwa/sync/syncQueue';
const stats = await getSyncQueueStats();
console.log(stats);

// Manual sync
import { syncPendingData } from '@/pwa/sync/backgroundSync';
await syncPendingData();
```

### Offline Data Not Loading

**Check**:
1. IndexedDB is accessible
2. Data was previously cached
3. No quota exceeded errors
4. Database schema version is correct

**Fix**:
```typescript
// Export database for debugging
import { exportDatabase } from '@/pwa/db';
const data = await exportDatabase();
console.log(data);
```
